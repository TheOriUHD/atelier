# Changelog

All notable changes per milestone. Tags: `v0.0.0-mN`.

## [Unreleased]

- **"Asking…" only while it asks.** Computer use read "Asking to use apps" and "Asking for the mouse and keyboard" even when no card came (apps you named, control already allowed). It now reads **Using your computer** unless a card is open for that step, and a finished step says **Got access to** the apps instead of "Asked to use".
- **Scratch folders don't show.** A Code or Cowork session started with no folder reads **No folder** at the top, in the folder menu and in moved notices, never `scratch-2026-…` or its path; it has no folder until you move it with the chip or the assistant does (ChangeDirectory's card says "It has no folder yet" instead of the scratch path).
- **Computer use in the background works again after you stop it with Esc.** Holding Esc during Full control locked the computer-use helper against all input until the next Full control, so a later Background session's clicks and typing were all refused and nothing happened. The lock now lifts when the turn that was stopped ends.
- **Apps you name yourself are allowed without a card.** When your own messages in the conversation name an app ("keep browsing in Chrome"), the assistant may use it at once, at its usual level. The name counts as people say it (Chrome for Google Chrome, Brave for Brave Browser, Word for Microsoft Word), as a whole word. In Bypass no app asks. Only your own messages count, not a co-op guest's, the assistant's or a screen's, and only on this computer's own backend. Taking over the mouse and keyboard still asks.
- **Nothing shows on your screen while Atelier works in the background.** The note below the menu bar ("Atelier is working in …") is gone.
- **Background computer use works the way Claude's and ChatGPT's do.** On a Mac, Atelier now acts in an app's window through SkyLight, macOS's private window-server framework, as both of those apps' computer-use helpers do (Claude's `app-cu-helper` and ChatGPT's `SkyComputerUseService` name the same calls; the recipe follows Cua Driver, MIT). The window takes events as the focused one without its app becoming active, and clicks, typing and scrolling reach it stamped with the window, the process and the point. Chrome and the other Chromium browsers, Electron apps (Slack, VS Code, Discord, Notion) and native apps take real clicks anywhere, typing (a character an event, emoji included) and the wheel while they stay behind the person's app. Checked on a Mac against Brave, an Electron app and a native app kept behind other windows: the front app and the window order never changed. Before, background input in Chrome did nothing at all (it ignores events posted the public way), and the keyboard-only workaround drove it like Full control without the glow. The private calls are looked up when needed; without them background input falls back to the public route.
  - **A covered window is drawn for its screenshot.** Chromium and WebKit stop painting a window that others hide completely, so after a page load its screenshot showed an empty page. For the screenshot the window is shifted just enough for a sliver to show past the windows in front (normal windows and the menu bar; see-through overlays such as the Dock's full-screen window don't count), then put back and waited for: about half a second, a strip at the edge of the screen.
  - **What would come forward is refused or undone.** Cmd+T and Cmd+N make a browser open a tab or a window in front of everything, so they're refused (an address goes into the tab there is: Cmd+L). An app that brings itself forward anyway is sent behind the person's app again at once (Cmd+, in Brave did), through Accessibility, and the agent hears what to avoid.
  - **A window an app raises over yours goes back behind it.** A link that opens a tab made Chrome put its window over Atelier's while Atelier stayed the app in front, and it stayed there (seen in a test run on a Mac). After each action the window order is checked too, for three seconds, and your window is raised back over it.
  - **An app's welcome or setup panel counts as its window.** Numbers past its license screen shows only a floating panel, which background mode didn't see ("Numbers has no window open"), so it asked for Full control. Panels below the Dock's level now count when an app has no normal window.
  - **Lists, right clicks and password fields aren't clicked in the background.** A list's menu would cover the person's screen and Chromium turns a right click into a left one, so both need Full control, as in Claude's helper. A password field isn't clicked (it would turn macOS's secure input on for everyone; one an app hides from Accessibility gets the focus moved on), and nothing is typed while secure input is on. Typing is refused while the person uses another window of the same app.
- **Atelier for Chrome: web pages through the browser itself.** A browser extension for Chrome, Brave, Edge and Arc lets the assistant open pages in background tabs of its own (an orange "Atelier" group, never your tabs), read them as text and a list of their links, buttons and fields, and click, type, choose from lists and scroll by name, as trusted input. In a test with a throwaway browser profile behind TextEdit: a tab opened in about 30 ms, a page read in 6 ms, a click or typing in 3–15 ms, a screenshot of the background tab in 30–60 ms, and the window order never changed (a link that opens a tab stays in Atelier's tab). It talks to the app through Chrome's native messaging (no open port; the app registers its helper with the browsers it finds and only Atelier's extension may reach it, with a token only your account can read). Settings › System › Computer use › Atelier for Chrome shows whether it is connected and the folder to load it from until it is in the Chrome Web Store. The new Browser tool is offered in Code and Cowork while it is connected; reading a page needs no permission, everything else goes through your permission mode.
- **Large connectors load when needed.** When your connectors' tools add up to more than about 6,000 tokens, the model sees a short catalog of them and loads the ones it needs with ToolSearch, as ChatGPT Chat already did. Measured on a Mac with two connectors (Notion and Fusion 360): every Cowork request carried about 72,000 tokens, about 60,000 of them those tools, so each step of a task took three seconds and more before the model started.
- **Terms and licenses wait for your yes.** In a test run, computer use clicked Continue on Numbers' first-launch license screen without asking. The assistant is now told to ask before it accepts terms, a license, a consent or cookie prompt, or signs you up for anything, and to say in each step's summary what it agrees to, so the auto-mode check can stop it too.
- **A background screenshot finds an app by part of its name** ("chrome" for Google Chrome), as opening an app does.
- **What's new shows everything since your last update.** Someone who skipped versions sees the newest first, then each version in between with its own notes (up to eight; the full changelog has the rest), and **More › What's new** shows the same versions again. Larger features get a segment of their own with a short silent clip, recorded from the real apps on throwaway data and bundled with the app (no request leaves it); with reduced motion a clip waits for a click. Atelier CLI's clip is the first, recorded by `apps/cli/scripts/record-clip.ts`.
- **Atelier CLI's footer fits narrow terminals.** Below 96 columns it leaves out "(shift+tab)", and the model and effort keep their place on the right while the rest ends in "…": at 74 columns the connection and the model ran together ("● this computeqwen3:30b").
- **Releases rehearse first.** `pnpm release` runs the Linux and Windows build machines' test steps on the commit (the terminal app's tests in a real terminal, with CI set) side by side before anything is tagged; `pnpm release --rehearse` runs only that, in about two minutes.

## [0.6.0] — 2026-11-10

- **Atelier CLI: Atelier in the terminal.** `atelier` in a project folder starts a Code session there, laid out like the terminal coding agents people know: the transcript printed as it finishes, each step one line (`● Read src/app.ts · 84 lines`, edits with their changed lines, commands with their last output), the line while it works, and a footer with the mode, the context, the connection and the model. Install with `curl -fsSL https://updates.atelierhq.dev/cli | sh` (Windows: `irm https://updates.atelierhq.dev/cli.ps1 | iex`): it installs for the person alone, brings its own Node.js and runner, and updates itself (`atelier update`), each version checked against the release key.
  - **With a server (recommended), or on its own.** Connected to an Atelier server, it uses the server's models and keys and its sessions open in the browser and the desktop app too (`/open`, `/resume`); the computer lends the folders opened in the terminal through the same device link and consent as the desktop app. On its own, it runs its own backend with the person's own providers, in `~/.atelier/cli`.
  - **A setup in four screens,** in the look of the server installer: the servers found on your network (or another address, or only this computer), signing in (the browser code at once; username and password on one screen; an invite; a new server's first admin), what the computer lends, and the model with the mode. Lists filter as you type and scroll in place.
  - **Pip,** the terminal app's mascot, a little clay figure in a painter's beret, drawn plain enough to read at six rows: it blinks, looks around and smiles in the header, hops while it works, and `/pip` says hello. The setup paints the ATELIER CLI wordmark in from the left, CLI in ochre beside ATELIER's clay.
  - **Keys and commands:** Enter sends (and queues while a reply runs), Ctrl+S sends into the running reply, Esc stops, Esc twice rewinds, Shift+Tab cycles Auto, Ask, Accept edits and Plan, Ctrl+O shows thinking and every step, `@` files, `!` shell commands, Ctrl+V images, Ctrl+G the editor. Slash commands for sessions, models, effort, context, cost, rewind, side questions, loops, permissions, connectors, the status line (Claude Code's `statusLine` command works), and the folder's skills and commands.
  - **A fullscreen view,** offered once: the conversation scrolls in the window (trackpad, wheel, Page Up/Down) and the message box stays at the bottom; `/fullscreen` switches to the classic view and back, and the session goes on.
  - **Print mode** for scripts: `atelier -p` with text, JSON or a JSON line per event, `--allow` rules, and `ATELIER_SERVER` and `ATELIER_TOKEN` for CI (`atelier token`).
  - **A server on your local network, on a Mac:** macOS asks once whether "atelier" may find devices on local networks (in iTerm and most terminal apps the program asks for itself; Terminal and SSH are let through). The setup says so, tries again every 2 seconds and goes on by itself once allowed, and the answer holds for later versions: the Mac build's Node carries its own UUID and Info.plist and is signed as `dev.atelier.cli`, as Apple's TN3179 asks.
  - **A background service** (`atelier daemon`) shares one backend (or one device link) among the person's terminals, lets a reply go on after its terminal closes, and with `atelier daemon keep` starts at login so the server can work in the computer's folders with no terminal open. Only its own user reaches it, with a token.
- **Terminals sign in through the browser:** the terminal shows a code, a link and a QR code; approved on the server's new `#/link` page by someone signed in there (password, passkey or single sign-on), it gets a sign-in of its own, once. Requests last 10 minutes; wrong codes are throttled; approvals and denials are in the activity log. Sign-ins of the terminal app show as "Atelier CLI" under Active sessions.
- **The download page has a part for each thing on it.** A switch beside the heading (Desktop app, Atelier CLI, Atelier Server) stays at the top as the heading shrinks into a bar, and its highlight follows the section being read. Atelier CLI has its install command for each system with a copy button and a terminal picture; the server section shows the one-line installer (`curl -fsSL https://updates.atelierhq.dev/install | sudo sh`) with the setup wizard's first question beside it, instead of the Docker Compose steps, which stay a link. The platform tabs slide. Pages load the stylesheet and script by version, so a browser never mixes a new page with an old cached stylesheet.
- **The device link and finding servers moved into core** (`@atelier/core/device`), and the app's session and tool-summary logic into a new `@atelier/client` package, so the desktop app, the web app and the terminal app share one copy.

## [0.5.5] — 2026-11-10

- **Share on your network: Atelier on this computer as a server for your other devices.** On **Run on this computer**, **Settings › Connection › Share on your network** asks for a password and a port (7340), then answers on the network: a browser on a phone, tablet or another computer opens the address it shows (or the Atelier app there finds it under **Found on your network**), signs in as you with the password, and works in your chats, with your models and keys, and in the folders this computer has. One account, no accounts to manage: everyone who signs in is you. It is plain HTTP for a network you trust, with a warning saying so. **Change password…** and **Sign everyone out** end every sign-in from the network, and turning it off closes the port. From the network: password sign-in only (no passkeys, invites or sign-up), and sharing, the screen lock and adding folders stay with this computer; a request from another site's page (its Origin, or a domain pointed at this computer) is refused.

## [0.5.4] — 2026-11-10

- **A command stuck in the system no longer stalls a turn.** A model searched the whole disk (`find / …`) and the turn waited on it for minutes with the model idle, which looked as if the model had stopped. Commands are killed after their timeout (2 minutes unless the model sets one), but a process blocked inside the system (a network volume that stopped answering, a macOS privacy prompt a read waits on) can outlive the kill, and the runner waited for it. It now answers a few seconds after the kill whether the process is gone or not, and tells the model the command is still held and to narrow it down instead of running it again. Stopping a turn answers the same way.
- **Models are told not to search the whole disk** (`find /`, `find ~`, `grep -r /`) but the workspace or the folders likely to hold what they look for, small local models too.
- **Switching between this computer and a server has its own page: Settings › Connection.** It was under Settings › Account as **Change setup…** (on this computer) or **Server › Switch…** (on a server), which went back to the first-run choice. The new page shows both ways to run Atelier with the one in use marked; **Switch…** opens what switching takes (a server's address, or one found on the network), and **Change…** on a server switches to another one. A server has to answer before anything changes: the app logs out of the server it uses only then. The profile menu at the bottom of the sidebar says where Atelier runs (**Running on this computer**, **Connected to atelier.home**) and opens the page. Settings search finds it as "standalone", "server mode", "switch server" or "set up again".

## [0.5.3] — 2026-11-10

- **Files you attach in Cowork and Code go into the session's folder.** An attached ZIP, model file or spreadsheet reached the model only as its text, or not at all (a ZIP was "cannot be read by this model"), so the agent couldn't unpack or open it although it had the tools: it said the folder was empty and asked for the file again. Each attached file is now put into the folder when the message is sent: in the root of a folder made for a session with no folder, under `.atelier/attachments/` in a folder of your own (with a `.gitignore`, so git leaves it alone). The model is told where; a name that is taken gets ` (2)`, and the same file sent again keeps its place. Only your own files: a co-op guest's don't go into the host's folder.
- **Looking through the folder reads as what it is.** An agent that read `.` to see what its folder holds showed as "Read ."; it now shows as "Listed the folder · 12 items" (another folder by its path), "listed the folder" in a run's summary, and "Looking through the folder" while it runs.

## [0.5.2] — 2026-11-07

- **Mistral: GLM no longer saves half-written files.** When a reply of GLM 5.3 or GLM 5.3 Flash runs out of room in the middle of a tool call, Mistral ends it as an ordinary tool call (`tool_calls`, not `length`), with that call's input cut off; Atelier read the half input as whole and ran it, so a Write saved half a shader, and the model wrote it again and ran out again, at up to 32,000 tokens a round. A Mistral reply that used its whole output limit, or a call whose input stops mid-JSON, is now taken as cut off: none of its calls runs, and the model is asked to send it again (a large Write split up). Seen and checked against Mistral's API with an API key and a Vibe key.
- **Mistral: a turn on a model that reasons gets the model's own output limit.** Mistral counts reasoning toward a reply's limit, and GLM reasons tens of thousands of tokens before it writes on a bigger task (23,000 of 32,000 on one measured first reply, 37,000 at High); Atelier's 32,000 at Medium (64,000 at High) cut such replies off with nothing written. Mistral's own Vibe sets no limit. The model's maximum now applies, within the room the context has left: 131,072 tokens for GLM, Medium 3.5 and Small 4, 262,144 for Large 4.
- **Mistral's model list as the API gives it now:** Medium 3.5 is listed as `mistral-medium-latest` (Atelier knew only its other names, so it showed the bare id and a 32,768-token limit); GLM 5.2 is known; DeepSeek V4.1 Flash takes Low, High and Max. Each model's `reasoning_effort` values were checked against the API: GLM 5.3 low, high, max; Large 4 low, medium, high; Medium 3.5 and Small 4 none or high.
- **Mistral: earlier reasoning goes back to every model that reasons** (GLM and DeepSeek included again: Mistral takes it, checked) and never to one that doesn't, which Mistral refuses after a switch from a reasoning model.
- **Mistral: tool calls keep their own ids** when one comes without an id, as `"null"`, or with the id of another call in the same reply (Mistral's Vibe guards against it; not seen in Atelier's runs).
- **Mistral: a reply that fails, shows nothing or is cut off leaves an outline in the log,** which **Copy diagnostics** carries: what was asked (effort, output limit, tools, messages) and what came back (fields, chunk types, how much text and thinking, tool-call pieces, the finish reason, the usage, Mistral's error). Never the words of the conversation.
- **Mistral's free plan** gives an API key (with low limits, and Mistral may train on what is sent with it); the provider form no longer says it has no API access.
- **Live tests for Mistral:** a real Code turn through a Mistral provider (`packages/core/src/providers/live-agent.test.ts`, on request with `LIVE_AGENT=1`), GLM's cut-off check, and a 64×64 test image (a single pixel reads as white to Mistral Small 4). From a git worktree they read the main checkout's `.env.local`.

## [0.5.0] — 2026-11-07

- **Co-op: work in one session together.** Click **Co-op** in a session's header and send the invite link. The people you let in work in the same conversation and the same folder: up to four in all, each writing their own messages and watching every reply as it's written. There is no account. The host lets each person in after comparing four emoji with them; someone let in before comes back without asking. Between two computers, the apps meet through an end-to-end encrypted relay at `coop.atelierhq.dev`, which can't read what passes and keeps nothing. On a team server, the host adds teammates instead, and nothing leaves the server.
  - **Whose models answer you** is each person's choice: the host's, while the host shares them, with a daily limit per guest in requests and dollars; or their own providers and plans, which run on their own computer with their own keys.
  - **Turns:** a message sent during someone else's turn waits as yours, or joins that turn if you choose. Stop keeps others' waiting messages. Retry and edits run as whoever clicked.
  - **The host's computer stays the host's.** In a guest's turn, commands and anything outside the folder ask the host, whatever the permission mode. Questions nobody answers within 5 minutes are declined. **Trust with approvals** lets a guest answer them. A guest can lend their own connectors to their turns, and each call then asks them.
  - **Nothing personal in a shared session:** no memory, personalization or project context, and no tools that reach outside the session.
  - **More together:** ask for a **second opinion** from another model, beside the first answer. Name a model with `@` for one message. Put **reactions** on messages. Turn on the **navigator**: your model looks over each edit in the others' turns. In Code, start a **parallel track**: an agent works on a task for you in its own git worktree, and the host merges its branch.
  - **Ending:** guests keep a copy of the conversation when co-op ends, unless the host switches that off. The host's computer stays awake while co-op is on.
  - **Your own relay:** a self-hosted server can run its own relay (`ATELIER_SERVE_COOP_RELAY=1`), and `ATELIER_COOP_RELAY` points desktops at it, or switches co-op between computers off.

## [0.4.4] — 2026-11-07

- **GLM and DeepSeek through Mistral show their replies:** these models, which Mistral hosts for their makers, can send their reasoning the way OpenAI-style servers do, and Atelier's Mistral provider only read Mistral's own format. A reply could then show nothing at all while the model worked until its output limit. Atelier now reads every common form, and no longer sends their earlier reasoning back as Mistral's thinking.
- **A reply cut off with nothing written stops instead of trying again:** when a model used its whole output limit without writing anything, Atelier asked it to continue, which sent the same request again. It now tries once more and then stops with an error that suggests a lower effort or another model.
## [0.4.3] — 2026-11-06

- **The conversation keeps its earlier messages through quick compactions:** when a session compacted twice in quick succession (a small context window and large tool results), the window could lose everything before its newest reply, the **Compacted session** lines included, until the conversation was opened again. The window now reloads the conversation once more when a second compaction lands while it is still loading after the first.

## [0.4.2] — 2026-11-06

- **See where an edit landed:** an edit in Code and Cowork shows the file's real line numbers and the three lines above and below the change, with whole lines instead of the fragment the model replaced. **Show the whole file**, the button in the corner of the diff, opens the whole file as it is now with that change in place, scrolled to it, as a permission card already could. Later changes above it don't confuse it: the view finds the change where it is now, and says so when that part was changed again since. A Write opens what it wrote. Edits made before this version keep their old diff without numbers, and their whole-file view looks for the change by its text. It works in a browser, on SSH hosts and in folders a desktop lends.
- **Permission cards show the lines around an edit too**, numbered, as the transcript does.
- **Move a session to another folder:** the folder in a Code or Cowork session's header is a menu of your other folders on the same computer or SSH host, with Open folder… / Browse remote folder… to add one. The conversation goes on there: files, terminal, Diff and tools follow, the model is told, and the transcript shows "Moved from app to api". A toast offers Undo. While a reply runs, the move waits for it to end ("Moving to api", or Stay in app to call it off); with background commands or sub-agents still running you're asked first, and they finish in the old folder. It works for folders a desktop lends a server too. A codespace doesn't move, and a session doesn't move to another computer.
- **Audio generation:** add an audio provider in **Settings › Admin › Media** (the page was "Image & video"), and any text model that can call tools can read text aloud, make music and make sound effects. Speech: OpenAI, ElevenLabs (your own voices included), Google Gemini (30 voices, two speakers), xAI, Mistral Voxtral, Cartesia, Deepgram Aura, Fish Audio, MiniMax, Groq, Azure, OpenRouter, Together, and servers on your own computer (Kokoro-FastAPI, Speaches, LocalAI, KoboldCpp, Chatterbox, Ollama, vLLM-Omni, Fish Speech). Music and effects: ElevenLabs, Google Lyria, Stable Audio, fal.ai, Replicate, ACE-Step 1.5, LocalAI, and ComfyUI (Stable Audio Open and ACE-Step checkpoints by themselves, any other sound model through a workflow). A card holds its place while the sound is made, then plays it with its waveform to seek on, by pointer or keyboard; speech has a speed button; nothing plays by itself. Sounds are in the **Images** page with a **Sounds** filter, in Usage (with the characters read out), and **SaveAudio** puts one in your folder in Code and Cowork. Each kind has its own default model, for you and for the server; each turn makes at most 6 sounds unless an admin says otherwise. Servers on their usual port are found by themselves, and **Make a test sound** plays a sentence from a provider before you save it.
- **Rewind after a move restores the right files:** rewinding past a folder change wrote the old folder's saved files into the new folder, and could delete files there that had the same names, because saved files were kept by their path inside "the session's folder". Each saved file now remembers its folder and full path, and Rewind restores it there; if a folder can't be reached, nothing is restored. This also applied after the assistant moved a session with ChangeDirectory. Files saved before this version still restore in the session's current folder.
- **Mistral, and Mistral Vibe:** **Add provider** has **Mistral**, with a key from Mistral's console, priced per token (list prices built in), and **Mistral Vibe**, with the Vibe key a Le Chat Pro or Team plan gives (Le Chat › Code › Vibe CLI), which spends the plan's Vibe allowance instead. Mistral has said such keys may be used outside Vibe, though not in its written terms. Models come from Mistral's list, one entry per model, without retired ones: Large 4 with Low, Medium and High effort, Medium 3.5 and Small 4 with thinking on or off, Ministral, Codestral, and the GLM and DeepSeek models Mistral hosts. Thinking shows and is sent back with the reply, tool calls from another provider's history keep working, PDFs go to the models that read images, and requests share Mistral's prompt cache per conversation. For a Vibe key the context ring shows the month's allowance with its reset date, a line above the message box warns from 90%, and the Usage tool reports it. In **Settings › Admin › Media**, Mistral can also make images, through its chat models' image tool (FLUX: one image at a time, by aspect ratio, and each costs the chat model's tokens too), and Voxtral speech and Mistral images can use a Mistral provider's key. Not yet run against the real service: the live checks run when `MISTRAL_API_KEY` or `MISTRAL_VIBE_API_KEY` is set.
- **Ultracode's field doesn't stay behind:** after leaving Ultracode, the effort slider could show faint grey cells (violet in light mode) across its track at another level, the next time it was opened. It happened when the popover was closed on Ultracode or while its field was still fading, or the level changed elsewhere meanwhile. The field now starts empty.
- **A retry's clock starts at zero:** the time under a running reply counted from when your message was first sent, so Retry, Retry with another model, Continue and a turn the assistant started by itself carried on from the old time. It now counts from when the reply started, and stays right after a reload. A message you send or edit counts from when you sent it, as before.

## [0.4.1] — 2026-11-03

- **Atelier keeps its icon on Windows after an update:** an update deletes `Atelier.exe` before it writes the new one, and Windows could keep the blank page it saw in that moment for the taskbar button and the shortcuts. Atelier's windows now carry the icon themselves, and its shortcuts (desktop, Start menu and every taskbar pin, whatever the pin is called) take their icon from a copy in Atelier's own data folder, which no update touches. ## [0.4.0] — 2026-11-03

- **Working outside the workspace folder works on a server too:** a Cowork or Code session on a Windows PC's folder, connected to a Linux server, took the PC's `C:\…` paths for relative names inside the workspace. It never noticed a path was outside the folder, so it never asked, never told the PC's runner to allow it, and the assistant was stuck with "outside the workspace" even after you said yes. Paths are now read the way the folder's own computer writes them.
- **One approval covers a folder elsewhere:** in Ask and Accept edits, allowing one look at a file outside the workspace allows looking at that folder for the rest of the session, so moving or reading a whole project doesn't ask for every file. Credential files still ask, and changes still ask per call, like edits in the workspace. Auto mode already did this.
- **The model you pick stays picked:** the model chosen in a conversation is the one the next new conversation starts with (Settings › General › **Start with the model I used last**, on by default; turn it off to always start with your default model).

- **Smaller Windows downloads:** there is now an installer for x64 and one for ARM64 (`Atelier-Setup-<version>-x64.exe`, `-arm64.exe`), each about half the size of the one installer that carried both. Installed copies pick theirs by themselves. The website's Windows tab offers the right one for your PC.
- **Copy diagnostics:** **Settings › System** and the screen shown when a page breaks have a **Copy diagnostics** button. It puts a plain-text summary on your clipboard to paste into a bug report: version, system, mode, Electron and Chrome versions, screen and theme, how many providers and connectors with their types, the last error and the end of the app log.
