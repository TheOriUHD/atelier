# Changelog

All notable changes per milestone. Tags: `v0.0.0-mN`.

## [Unreleased]

## [0.2.12] — 2026-10-29

- **Computer use on Windows:** the same as on the Mac (Full control and Background, the denied apps, holding Esc to stop), with nothing to grant first. Shortcuts use Ctrl, and apps running as administrator can't be used. The password managers start on the denied list there too.
- **Atelier no longer stays invisible on Windows when something goes wrong at start:** a start that fails says why and where the details are (`%APPDATA%\Atelier\logs\main.log`) instead of leaving Atelier running with no window, a window that doesn't paint is shown after 5 seconds, a crashed page loads again, and opening Atelier again shows its window even when it never appeared.

## [0.2.11] — 2026-10-29

- **Computer use (macOS, Run on this computer):** the assistant in Code and Cowork can see and use apps on your Mac when a connector or the shell can't do the job. Turn it on in **Settings › System › Computer use**, which also has macOS's Accessibility and Screen recording permissions, your denied apps (password managers to start with) and the apps you allowed for good. The assistant asks for each app on a card, where you choose what it may do there (browsers see only, terminals and editors see and click), and asks before it takes over the mouse and keyboard. **Full control** takes over the computer as it is: no cards, anything in any app but your denied ones (terminals and editors included), screenshots of the whole screen, nothing hidden. While it has them, the screen's edges glow and a panel says "Atelier is using your computer · Hold Esc to stop": it keeps them for the whole task and brings Atelier back to the front when it is done, holding Esc for a second stops the reply, and using the mouse or keyboard yourself only pauses it. Clicking and typing follow the permission mode like any action: Bypass runs them, Auto's reviewer stops only for what matters (purchases, sending messages, deleting, accepting terms, passwords), Ask asks. Your denied apps never show in its screenshots; it never types into password fields or clicks links in Mail and Messages. See [Computer use](https://docs.atelierhq.dev/computer-use/).

- **Suggested replies in Code and Cowork:** when a reply ends, the empty message box shows a short guess at your next message in grey (what you usually say at that point, an answer to the reply's question, or the next step it offered). **Tab** puts it in as your own text; it steps aside while you type and comes back whenever the box is empty again, until you send. The small model writes it at the lowest priority, so it never delays a reply. Settings › Code › Suggested replies turns it off.

- **The agent does the work it is asked for, also when the request is a question:** "Can you start?" or "can't you look at the plugin?" now get the work done, not an answer saying it could; a "yes" or "go" is the go-ahead, and a turn no longer ends on "the next step is …" when the agent could take that step, or on an apology and a plan after the person says the result falls short. GPT models (GPT-6 Astra in a long Code session) read the old wording as "answer questions, act on orders" and kept stopping to explain.

- **A session the assistant moved to another folder shows that folder:** after ChangeDirectory, the sidebar listed the session under "Ungrouped", the Terminal said "This session has no folder" and code blocks had no Run button, until the app was restarted: the folder was new to the window's list of folders and nothing told it. The move now sends the updated list, and a window that meets a session in a folder it doesn't know reads its folders again.

- **Several windows, devices and the browser stay in step** (found by an audit for quirks like the one above, where something changed and a window kept an old copy until a restart):
  - Switching a reply's branch or rewinding in one window moves every other window on that conversation too; before, they kept the old branch, and the next message there cut the transcript down to that one message.
  - A deleted conversation says "This conversation was deleted." wherever it is still open (another window, the other half of a split view), instead of failing when you send.
  - An answered SSH question (host key, password) closes in every window, not only the one that answered.
  - Side chats started or closed in one window show in the others.
  - Deleting a project takes its chats out of it everywhere (before, "/clear" in one of them opened the deleted project); a project's chat count no longer counts side chats or archived chats, and follows forks and Continue in Cowork.
  - A removed device leaves the Devices list in every window; changing someone's role updates their model list and connector details right away; turning a plugin on or off, or Claude Code compatibility, updates every window's skills and `/` menu.
  - What this computer lends a server, changed in one window, shows in the others (in server mode).
  - "Keep computer awake" is the same in every window, so closing the window you switched it in no longer lets the computer sleep.
  - "Change server" reloads every window, not only the one you clicked in; a window closed while it recorded a keyboard shortcut no longer leaves the menu without its shortcuts.
- **Code and Cowork follow changes they didn't make:** the git bar, Changes, Files and Rewind refresh when a background command or sub-agent ends, when a reply ends, a moment after the Terminal goes quiet (a `git commit`, a checkout) and when the window comes back to the front (an edit in another editor).
- **Chat and Cowork conversations start fresh when you switch:** the side chat panel and Cowork's file preview no longer carry over from the conversation you were in.
- **Artifacts:** the Artifacts page opens a Code session's artifact in Code (it opened the Chat view), and follows chats deleted or changed elsewhere.
- **Show in Finder and Open in Cursor / VS Code work for a folder the agent moved a session to** on "Run on this computer"; before, they said the folder wasn't one you opened, even after a restart.
- **Server mode:** an account that signs in with a temporary password lends this computer once the new password is set (before, its folders stayed unavailable until the app restarted); a folder already in your list is no longer asked about again ("Trust this workspace?") when you open it from this computer.

- **Run in terminal for PowerShell:** code blocks marked `powershell`, `pwsh` or `ps1` get the Run button too. On Windows the terminal is PowerShell, and that is what models write there; before, only `bash`, `sh`, `zsh` and `fish` blocks had it.

## [0.2.10] — 2026-10-25

- **Commands are color-coded:** the commands the assistant runs, in Code and Cowork steps, in Background tasks and in the "Allow Atelier to run …?" prompt, are highlighted like code blocks in your syntax themes (Settings › Code). Bash by default, PowerShell when the command reads like it (cmdlets such as `Get-ChildItem`, `$env:`), and a here-document's body in its own language: `python3 - <<'EOF' … EOF` as Python, `node <<EOF` as JavaScript, `cat > app.ts <<'EOF'` by the file's extension.

## [0.2.9] — 2026-10-25

- **Give the assistant an MCP server and it can use it:** paste an address like `http://127.0.0.1:27182/mcp` (Fusion 360's) into any conversation and the assistant asks to add it with the new AddConnector tool, on a card that shows the address. **Add connector** puts it with your connectors and its tools work in the same conversation from the next step. On a server it becomes one of your own connectors, and an address on your computer is reached through the desktop app where you clicked Add; on "Run on this computer" it joins Settings › Connectors. Before, the assistant could only try WebFetch, which refuses local addresses ("127.0.0.1 resolves to this machine"). WebFetch now points to AddConnector for addresses ending in `/mcp` or `/sse`.

- **A connector that can't be reached says why:** "Can't reach 127.0.0.1:27182: nothing answers there (connection refused)." instead of "Version negotiation probe failed: fetch failed", also for one reached through a desktop app. On a server, an admin connector at `localhost` or `127.0.0.1` adds that this address is the server itself and points to Your connectors, and the URL field in Settings › Admin › Connectors says so while you type it. The server's log no longer writes `"error":"undefined"`.

## [0.2.8] — 2026-10-25

- **Connected to a server, the desktop app keeps your computer's SSH hosts and No folder:** the server keeps your chats, settings and permissions; your computer lends the rest to your sessions there. SSH hosts are reached with this computer's `ssh`, keys, agent and known hosts (Atelier puts its runner on the host from here; password and host-key questions show in the app and in the browser), and a session started without a folder gets one made on this computer. The server may reach an SSH host from here once you chose it here, and make folders here once you allowed it ("Make folders on this computer?"); Settings › System lists both, with Remove. Another computer's SSH folder shows under Remote Control. The device link speaks version 2 (`hello`, `start`, requests); older desktop apps and servers keep working as before.

- **Your own connectors on a server:** everyone can add their own connectors in Customize › Connectors › Your connectors, not just the admin. A connector that runs a program runs on your computer through the desktop app, and only exactly the command you allowed there (a changed command, argument or variable name needs your say-so again; variables like `PATH`, `NODE_OPTIONS` or `LD_PRELOAD` are refused). Its keys are kept for you alone, `${VAR}` is filled in from your computer's environment, and Import from Claude Code reads `~/.claude.json` there. One at an address on your network is reached through your computer; the admin's connectors stay shared and run on the server, and their name wins.

- **Your computer's config in Code sessions on a server:** a session in a folder on your computer gets your `~/.claude` and `~/.atelier` instructions, skills, commands, agents and Claude Code plugins from that computer, and its `settings.json` permission rules and hooks, as the desktop's own backend would. An SSH folder reached through it gets the instructions and skills, not the hooks. Customize lists them "From <computer>", and you switch its plugins for yourself. The server never reads credentials, history, transcripts, `~/.claude.json` or `~/.ssh`; Settings › System turns it off.

- **Models on your computers:** connected to a server, the desktop app adds the Ollama, llama.cpp or LM Studio on its computer, and its ChatGPT Chat, under Settings › Your models. Only you see and use them, listed under your computer's name in the model menu, and only while that computer is connected (a chat on one says so when it isn't). Requests go out from your computer, so a model server that only listens on localhost works.

## [0.2.6] — 2026-10-24

Atelier refuses keys another shortcut or the system already uses and says why, the desktop menu bar shows your keys, and the change follows your account to your other devices.

From 90% of a window a line above the message box says so in every mode ("You’ve used 92% of your ChatGPT 5-hour limit. Resets in 1 hr 10 min."); dismissed, it stays away until that window resets. Click again to stop; opening another conversation stops it too.

- **A ChatGPT limit's countdown turns into the time it resets:** in the context popover's Plan usage limits, click "Resets in 4 hr 25 min" and it reads "Resets 14:25" (with the weekday when it resets on another day); click again for the countdown. The choice stays. Times there follow the computer's 12- or 24-hour clock, not the app's language: the desktop reads it from the system (macOS's 24-hour switch, or its region, so English with region Germany is 14:25 where it said 2:25 PM; Windows' short time format; Linux's time locale), and a browser keeps its language's clock.

## [0.2.3] — 2026-10-22

- **A Mac no longer gets stuck on "Couldn’t download Atelier …: ENOTEMPTY":** an update that was downloaded but never installed (because a newer copy was installed by hand) stayed in the update folder as a whole app, and Electron's file functions can't delete an app's `app.asar`, so every later update failed while clearing it. ## [0.2.2] — 2026-10-22

- **A setup wizard for the server: `curl -fsSL https://updates.atelierhq.dev/install | sh`:** a full-screen terminal program (`atelier-setup`, Go, `setup/`) that checks the machine, asks how people will reach the server (by default this machine's address on the network, no domain; or HTTPS with a domain through Caddy in the same Compose project; your own reverse proxy: Caddy, nginx, Traefik, Nginx Proxy Manager or a Cloudflare Tunnel, whose exact settings it prints and saves; or Tailscale), shows every file before writing it, starts the containers, tests the address like a browser would (DNS, certificate, health, the live WebSocket connection, a sign-in request) and creates the first account. `atelier-setup doctor` repeats the test and names the setting to change when a page loads but spins forever, `update` pulls new images, `plan` prints what an install would do. Run it again on a machine it set up before and it recognises its own containers (and the ports they hold): you can reinstall over them keeping accounts and chats, remove them, or leave them. Busy ports 80 and 443 only matter for the domain choice. The script checks the download against the checksum written into it; each release builds the program for Linux and macOS (amd64 and arm64) and publishes it with the script on the update feed. The feed Worker serves `/install` and `/setup/<version>/…`.

- **Third-party notices ship with Atelier:** `THIRD_PARTY_NOTICES.md` (generated by `pnpm notices` from what is installed: the JavaScript packages the app and server bundle, and the Go modules in the runner and the setup program) is in the desktop app's resources and in the server image beside `LICENSE`; `atelier-setup licenses` prints the setup program's own. The website and the docs serve their fonts' license as `/fonts/OFL.txt`. A release is refused while the notices are out of date.

- **A server that refuses a browser's address says so in its log:** behind a reverse proxy, a page that loads and then spins forever ("Cross-site WebSocket refused") left nothing in the server's log, so a proxy that had moved to another address (and was no longer in `ATELIER_TRUSTED_PROXIES`) took a hunt to find. The log now has one line per browser address and sender every ten minutes: the address the browser used, the one the server sees, who sent the request and which setting to change.

- **The Updates row says what is going on when there is nothing to check:** a copy with no update feed (the public one removed with `ATELIER_UPDATE_FEED=off`, and no server to ask) read "Updates come from an Atelier server; this computer runs its own backend", which didn't say what to do. It now reads "This copy has no update source, so it can’t check for new versions. Get them from the Releases page.".

## [0.1.11] — 2026-10-21

- **Stopping background work takes one call:** `TaskStop` takes `task_ids` (several) or `all: true` (every running task: commands, sub-agents and loops), so an agent told to stop the background work no longer stops them one by one. The card reads "Stopped all background tasks".
- **Agents can read the clock and their limits:** a `Time` tool gives the date, time, time zone and offset (the date in `<env>` is the start of the session and goes stale; the time of day was told nowhere), and a `Usage` tool gives a ChatGPT plan's weekly (and, off Pro, 5-hour) window with the share used and the time until it resets, or what a priced API has cost this session, today and over the last 7 days. `Usage` is offered only where there is something to report (a ChatGPT plan, Anthropic, OpenAI or an OpenAI-compatible API, or a model with a price set), not to sub-agents or local models; compact-tier models get neither tool (their prompt has a 16,000-character budget). Both only read, so they never ask.
- **A finished message shows how long ago it was sent:** "11 minutes ago" in the row of its buttons (yours and the reply's); click it for the exact date and time, and again to go back.
- **The running line counts the whole turn:** the summary line of a run of tool calls showed the time of the step it was in, restarting with every step; it now counts from your message until the reply is delivered, as the line at the bottom already did. A running command's own row still shows its own time.
- **The Reply pill no longer goes see-through on hover:** its hover tint replaced the solid background instead of lying over it, so the text under the pill showed through.
- **Settings changes can't bring back an older state:** a reload started by a file change could read the settings file before a second write and apply it after, so the older settings came back in memory until the next change (a web search provider read as "auto" a moment after it was set). Writes, resets and reloads now run one after another.
- **One command makes a release:** `pnpm release <version>` (`deploy/ship/`) runs the checks and tests, builds the Linux packages, the server images and the end-to-end suite on a Linux machine, the Windows installer on a Windows machine and the signed and notarized Mac apps here, side by side, checks every file against its update file, signs them, asks once, then publishes the GitHub release, the update feed, the website and the docs and checks what is live. The Package and Server image workflows on GitHub are manual fallbacks now (docs/updates.md, "Releasing").

## [0.1.10] — 2026-10-21

- **On a server, one person's sandbox commands can no longer read or change another's folders:** every account used to share the sandbox container's one Unix user, so Bash in one chat could list, read, edit or leave files in another account's `chats/<account>/…` (only Read was kept to its folder). Each account now runs as a Unix user of its own in the container (`sbx000`, `sbx001`, … 256 of them, `ATELIER_SANDBOX_SLOTS`): the server gives an account the lowest free one the first time it needs the sandbox, keeps it for good in `sandbox/slots.json` and logs in as that user, so the runner, every command, caches and temporary files run as it, in a home and chat folders of mode 0700. sshd runs as root only to switch users; the image has no setuid, setgid or file-capability program and no sudo (the build fails otherwise), and the compose file adds `no-new-privileges`, `cap_drop: ALL` and the six capabilities sshd needs. The sandbox also remembers which account each user was first given to and refuses a user the server later hands to another (a lost `slots.json` cannot give one account another's folders). Tried against a real container (Debian 12, Docker 29, default seccomp, the compose limits): another account's `ls`, `cat`, writes, deletes, renames, `chmod`, planted files, `su` and `setuid` all fail, its own folder, `git clone`, gcc, npm and pip work, and the 2 CPU / 2 GB / 512 process limits still apply (a fork loop stopped at 508 children). What accounts still share: CPU, memory, disk and network, and each other's command lines in `ps`. **Updating:** pull and recreate both images; the compose file you have keeps working. Chats made before keep their paths: what the old shared user left is locked to root at start, and an account's `chats/<account>/` folder is handed to its user the next time its chat uses the sandbox. `ATELIER_SANDBOX_USER` is unset by default now; set, everybody logs in as that one user, for a sandbox container you built yourself. Namespaces (bubblewrap) were not an option: the default seccomp profile refuses them.

- **A codespace asks "Trust this workspace?", and the backend keeps the answer:** local and SSH folders asked, a codespace never did, so a repository's own `.atelier/` and `.claude/` settings applied the moment a session worked in it: its hooks ran commands on the codespace, its allow rules skipped the questions, and its instruction files, skills, commands and agents were loaded. The question is now asked before a codespace is woken or created (Cloud › Open a repository…, a codespace from the Cloud menu, Settings › Cloud › Use as folder), in the browser too (the dialog was only mounted in the desktop app, so there the question was answered yes by itself). The answer is stored on the folder (`workspaces.trusted`, new `workspaces.trust`; `workspaces.addCodespace` and `codespaces.open` take `trust`), and until a folder is trusted the backend ignores its hooks, permission rules, instruction files (nested ones too), skills, commands and agents, whichever client added it. Codespaces are trusted one at a time: trusting one doesn't trust another, even of the same repository. Codespaces you opened before are marked **Not trusted** (folder chip, Settings › Folders with a Trust button) and are asked about when a session is about to start in them, so their hooks and project rules stop applying until then. Folders on this computer and SSH hosts work as before. Codespaces have not been verified against a real GitHub account.
- **A model that goes quiet says so:** when a model's server sends no output for a minute (a hung runner or stalled GPU gives no error for up to 15 minutes, and a long tool call is silent too), the line under the transcript now reads "No output for a minute, it may be writing a long call", then after two minutes that the model may have stalled and that Stop ends the turn, and clears itself with the next output. This makes the silent stop visible; its cause isn't found yet.

- **Subscription and billing limits stop a turn at once:** a "usage limit reached", "insufficient quota" or "weekly limit" answer is not a lost connection any more, so it isn't retried ten times; the turn ends with the message. Rate limits that clear by themselves still retry.
- **Ollama models whose tool schemas can't be compiled into a grammar keep working:** after "failed to parse grammar" or "failed to initialize samplers" the model's tools are described in the prompt instead, and the choice is remembered for that model until the app restarts.
- **Thinking is its own switch on models that can only think on or off:** in the effort popover, on by default and recommended; it disappears from Extra upwards, where thinking is always on. Set it before the first message and it becomes your default for new sessions; each session can differ afterwards. Sub-agents and side chats inherit it. **Low** is now token-efficient on every model (brief answers, no needless steps, no sub-agents for small things), and the Agent tool's description weighs the cost of delegating against the gain from parallel work.
- **Remote control (servers):** on by default for server accounts (not offered on "Run on this computer"); switch it off for the whole account in Settings › Account or for one conversation in its header. A conversation with remote control off is only visible to the sign-in that made it: it's absent from other devices' lists and its live updates stop.
- **ChatGPT Pro shows as Pro 100, Pro 200 or Pro 500** and only its weekly limit (the plan has no 5-hour window). The subscription provider is named **ChatGPT Plan**.
- **Automatic context size for Ollama models, with VRAM in decimal GB:** the budget you enter (GB, as GPUs are sold) sizes each model's window from its architecture and weights (Qwen's hybrid layers count only their attention part), with a tighter reserve; Settings › Models has a library with your models and a searchable catalog, and a model's context number updates the moment a provider is saved.
- **Smaller:** compaction shows its elapsed time instead of a counter that never moves; a sub-agent's card says whether it is retrying, loading, reading or compacting; images the agent viewed read "Looked at" with thumbnails of 32 × 24 px; the memory budget settings are grouped with the technical detail folded away.
- **ChatGPT Chat (experimental, desktop):** a second way to use a ChatGPT plan, through a browser session Atelier manages (hidden except for signing in and "Open session"); the connector tools of a conversation are listed on request (`ToolSearch`) so the page's prompt stays small. ChatGPT's own limits apply.
- **ChatGPT Chat keeps ChatGPT's formatting and carries on in one chat:** replies used to arrive as flat text (tables as tabbed words, bullets without markers, code blocks with a "Python" label and no fence, source chips as stray lines). Atelier now reads the page's own markup back into Markdown: headings, nested lists, tables, fenced code with its language, inline code, links (a source chip becomes a link, without ChatGPT's tracking), math as TeX, and text that stays exactly as written, so a tool call in the reply still parses. The next message of a conversation goes into the same ChatGPT chat and types only what is new (about 0.1 s to send instead of 2 s, and ChatGPT keeps its own context), and starts a new chat with everything whenever the conversation changed (an edit, a retry, a stopped reply). Chats are **temporary chats** by default, so they stay out of your ChatGPT history and memory; turn that off in the provider's menu (Settings › Providers). A leftover request from a closed or crashed backend no longer blocks the next one with "already generating", and a reply counts as finished only once it looked finished twice in a row, so a last paragraph isn't cut off.
- **ChatGPT Chat for work and code: ChatGPT's own choices as the effort control, images, and tool calls that hold up.**
  - **Models and effort:** the models and the stops of ChatGPT's own picker are read from the page (today "GPT-6" and "GPT-5.6 Sol", each with Instant, Medium, High and, on the higher plans, Extra High and Pro) and become the model list and the **detents of the effort slider** for these models, under ChatGPT's names, with Pro marked as having its own small allowance. A plan without a stop doesn't get it. Ultracode isn't offered here. The page is set to the model and stop before each message (only when it differs), and the context window is 128k tokens instead of a guess of 32k.
  - **Images and files:** images and PDFs go to ChatGPT as attachments (up to 10 per message, 20 MB each, the way ChatGPT takes them), a text document is put into the message, and a message in a conversation that goes on sends only the files it adds.
  - **Tool calls:** left to itself, ChatGPT often does not use the tools it is given: it runs a command or fetches a page in **its own Python sandbox** and reports a result that never happened on your computer, or declines ("I can't run npm test from this chat, please paste the output"). Measured on the real page with six everyday requests ("list the files here", "read notes.txt", "find every .test.ts", "create hello.txt", "what OS is this", "run the tests"): about two thirds went to the right tool. Calls are now asked for inside a fenced code block (the page shows those exactly as written, so `__init__.py`, globs and URLs survive), the chat opens with a short framing and every message ends with a reminder, and a reply that has no tool call but reads like a sandbox result or a refusal is **sent back in the same chat** ("that is not how this chat works: write a tool call") with what it said taken back, twice at most. After that, 18 of 18 requests ended in the right call (4 needed one correction, each worked at the first retry and took 9–17 s instead of 4–8 s), and 5 ordinary questions with tools available were left alone. A reply from the sandbox that survives both corrections fails the turn with a plain message; a refusal that survives is the answer. The obvious ways to make the framing firmer ("the tools are real and connected") made ChatGPT use its sandbox more (0 of 12 right), so the wording is measured, not guessed (`apps/desktop/scripts/chatgpt-live/tool-matrix.js`).

- **No more step limit:** a turn used to stop after 60 to 400 tool steps ("Stopped after 60 tool steps. Send a message to continue."; 60 was the cap for compact-tier models, which is most local ones), which cut off slow, thorough models mid-build. A person's own turn now has no cap. What guards it instead is a loop check: the same call with the same result is flagged to the model on its 6th time and the turn is stopped on the 15th ("Stopped: the same action ran 15 times…"), polling a background command exempt. Sub-agents, which run unattended, keep a ceiling of 200 steps (150 on the compact tier), and a defined agent's `maxTurns` still wins.
- **Sign in with ChatGPT** (desktop app and server): the models in your ChatGPT plan as a provider, signed in the way OpenAI's Codex does (Settings › Providers › Add provider › ChatGPT subscription, an entry beside the OpenAI API: a browser sign-in on the desktop or a device code on a server, then the provider and its models appear; Remove signs you out). Usage counts against your plan, whose windows show in the Code context popover. Unofficial: OpenAI documents this sign-in for its own tools, not as an API, so it can change or stop working. Atelier signs in on its own (it doesn't read or share Codex's login), keeps the tokens encrypted, renews them safely and sends requests under its own name. The model list is asked for with Codex's current version, so the newest models show as they do in Codex.
- **Running times read as minutes and seconds** ("2m 4s", "1h 3m") in the compact activity line, not "124s".
- **Background commands after a restart:** asking for the output of a command started before the app restarted now tells the model it stopped with the restart and should be started again, instead of a bare "unknown exec" error; the background commands line no longer animates once its turn is over.
- **Cloud works like the desktop app's:** folder menu › Cloud › **Open a repository…** lists your GitHub repositories (own, shared and organizations', newest push first) with a search box, Enter opens the top match and Refresh list reloads. Picking one does the rest: it uses that repository's codespace, creates one on the largest machine your account can use with GitHub's longest idle timeout (4 hours) when there is none, and shows the time while it comes up. A codespace that went to sleep is woken by itself when you come back to its session or send a message, instead of showing "stopped". Settings › Cloud keeps the manual New codespace dialog (machine and timeout by hand).
- **Send while the agent works:** the box stays live during a run (Stop while it is empty, Send once you type). The message shows under the conversation as waiting, joins it at the agent's next step with a note (or starts the next turn when the reply was already ending; slash commands and prompt hooks wait for a turn of their own), and has **Take back** (its text and files return to the box) and **Send now**, which cuts the step in progress off and sends it; what the agent had done stays and it carries on from there. Stop leaves nothing waiting and returns the texts to the box. The Stop button is the clay one with a filled square, and Esc stops while the box is empty.

Approving trusts the folder and moves the same conversation there: the header, Files, Diff and terminal follow, its tools run in the new folder, the result tells the model about the branch and the new folder's AGENTS.md / CLAUDE.md, and the system prompt is rebuilt for the next turn. It always asks, also in Bypass; codespaces (one repository each) and folders lent by another computer can't be moved with it.
- **The opened compact line is one grouped list:** clicking "Ran 5 commands …" (or the live line) opens one bordered group with a row per step instead of a stack of cards. A command's row is titled by its description and opens to the command in its own card with the output under it; edits open to their diff, other calls to their result; a failed step says so at the row's end.

## M2a–M5 (tags v0.0.0-m2a, v0.0.0-m2b, v0.0.0-m3, v0.0.0-m4, v0.0.0-m5, 2026-10-14)

Feature-complete and passing the local gates (typecheck, lint, 889 unit tests, 32 E2E on web and desktop, macOS
packages).

### M2a — Code core
- **Go runner** (`runner/`): one static binary per OS/arch (six builds plus a checksum manifest) speaking JSON-RPC over stdio. Path-scoped file operations, native glob and grep (gitignore-aware), shells with a persistent working directory, processes and PTYs. A TypeScript client and a conformance suite run against the real binary.
- **Workspaces:** trusted folders at their git top level, one runner per workspace (started on demand, stopped when idle), a shell per session. Packaged desktop apps bundle their OS's runner builds.
- **Code tools** with Claude Code's names and parameters: Read, Write, Edit, Glob, Grep, Bash (live output), BashOutput, KillShell, plus TodoWrite, AskUser, ExitPlanMode and Agent (sub-agents as child sessions whose permission prompts appear in the parent).
- **Permissions:** Claude Code rule syntax, deny → ask → allow → mode, compound commands checked part by part, a dangerous-command detector, inline prompts that survive reloads, "allow for this session" and "always allow". Rules come from system settings, the project's `.atelier` and `.claude` settings, and the person's own list.
- **Prompts:** Code and sub-agent templates (full and compact). Code sessions get an `<env>` block and the instruction files: the system AGENTS.md, `~/.claude/CLAUDE.md` on desktop, and the project's CLAUDE.md, AGENTS.md, CLAUDE.local.md and `.claude/rules` (with `@imports`).
- **Code view backend:** file tree, file reads, git status and diffs (untracked files included), and terminals on the runner.
- **Fixes from the M1 review:** only the active branch is loaded (recursive CTE), pre-turn auto-compaction keeps the new request verbatim, snapshots re-read when stored state changes underneath them, and rotated provider keys take effect on the next request.
- **Code view:** Code mode with a workspace picker (local, SSH and codespace folders), tool cards with live Bash output and diffs, permission/plan/question cards, a todo widget, a Files/Diff/Terminal/Tasks side pane, a permission-mode picker, `/` commands and `@` file mentions.
- **Runner health:** heartbeats on runner channels, SSH keepalives and device-link pings; runners start once per workspace and failed remote starts are retried.
- **Settings › Code** (personal rules, syntax themes, code and interface fonts) and **Admin › Code** (default mode, system rules, additional directories, Claude Code compatibility, system AGENTS.md).
- **Device link:** a desktop signed in to a server lends its runner for folders trusted on that desktop.

### M2b — Hooks, checkpoints, git, evals
- **Hooks** in Claude Code's format (PreToolUse, PostToolUse, UserPromptSubmit, SessionStart, Stop) from system, project, `~/.claude` and plugin settings, run in the session's workspace; stopping a turn stops them.
- **Checkpoints and Rewind:** files are saved before their first change in a turn (sub-agent edits included); Rewind restores files, the conversation, or both.

- Plugin installs can no longer escape the plugin cache; downloaded archives drop links and are capped in size.
- Settings can't reference a person's own secrets; regular users no longer receive system hooks or web search keys.
- A hook's approval no longer skips the dangerous-command prompt, and rewritten tool input is checked against the rules again.
