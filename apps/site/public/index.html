Code. Agentic sessions in your repositories. It reads, edits and runs commands; you review the diff, reject a hunk, commit and open a pull request. Five permission modes decide what it may do without asking.

Where you’d expect everything to be.

There’s no tour. The sidebar is on the left, the composer is at the bottom, and artifacts open beside the conversation.

The layout

A Chat and Code toggle sits at the top of the sidebar. In Chat, Cowork, Projects and Artifacts are listed under it, and Settings opens as a dialog.

The shortcuts

/ lists skills and commands. Shift Tab cycles permission modes. Ctrl U attaches a file, and you can drop or paste one too.

Your files

Agent skills, commands, sub-agents and hooks are read where they already live, and MCP config can be imported.

Any model, local or hosted.

Point Atelier at a model on your own machine, add an API key, or sign in with a ChatGPT plan or GitHub Copilot, then pick the model in the composer. ChatGPT Chat, which drives a signed-in browser window, is an experimental option.

  • Local servers are detected. Ollama, llama.cpp and LM Studio on their usual ports are offered as one-click suggestions.
  • Reasoning effort from Low to Max. Models with a setting of their own get it, the others are guided by a short note, and ChatGPT Chat uses ChatGPT’s own steps.
  • Small local models get per-model overrides for the tool calling they struggle with, and hosted ones show what a session cost.

Built for real work.

The parts that matter once a model is changing your code or running for an hour: control over what it does, and an easy way back.

Approvals you control

Auto, Ask, Accept edits, Plan and Bypass: pick how much it may do. Commands like sudo, rm -rf outside the folder and force pushes ask first unless you chose Bypass. In Auto a separate review request to the model decides instead, and Plan mode refuses commands.

Review and undo

See the diff against the last commit, what’s staged, or what the session changed. Reject one hunk, commit, push and open a pull request. Rewind restores files, the conversation, or both.

Work where the code lives

A folder on this computer, or a machine over SSH using your own keys and config. Each session without a folder gets a scratch folder of its own.

Several sessions at once

Split view puts up to four side by side. Type while one works: your message joins at the next step, or send it now to interrupt.

Extensible

Skills, plugins, hooks and MCP connectors. Connectors sign in with OAuth, and each tool can be set to Ask, Always allow or Block.

Reasoning effort

Low to Max, and in Code Ultracode on top: it plans, sub-agents investigate in parallel and others check the results. Slower, and it uses far more tokens.

Web search built in

Nothing to set up and nothing to pay for: Atelier searches the web itself and cites what it used, with any model that can call tools. Bring your own SearXNG, Brave or Tavily instead.

Memory you can see

It can remember lasting preferences and facts across chats. You can read and delete every entry, keep sensitive topics out, and leave a chat out entirely with a temporary one.

Prompts in the open

Every system prompt, note and tool description Atelier sends is published word for word, and you can override any of them with a file in your config folder.

Yours to run, and yours to keep.

There is no Atelier cloud. The desktop app runs its own backend, and the web app is the same backend in a Docker image.

  • Everything lives in one folder you control. Keep conversations as long as you like, export them as a zip, or delete them all.
  • No telemetry. Requests go to the model providers and connectors you set up and to the search engines and pages web search reaches. The desktop app also checks for updates.
  • Several people can share one server. Invite codes, passkeys, and provider keys encrypted at rest.
# 1. copy deploy/compose.yaml and deploy/Caddyfile
#    and put your hostname in both
docker compose up -d

# 2. read the one-time setup token
docker compose logs atelier

# 3. open your site, create the admin, add a model

Up and running in a few minutes.

  1. Install

    Download the desktop app, or run it from source or in Docker. macOS builds are signed and notarized. Windows builds aren’t code-signed, so SmartScreen asks you to confirm the first launch.

  2. Add a model

    Open Settings, then Admin, then Providers. Local servers on their usual ports are offered as one-click suggestions.

  3. Start working

    Type in the composer, press / for commands, or switch to Code and pick a folder.

What it won’t do

  • It isn’t a hosted service. You run it, and you hold the data.
  • It doesn’t make a weak model strong. Small local models can struggle with tools.
  • Auto mode isn’t a security boundary. Review sensitive work yourself.
  • There are no mobile apps. The web app has a phone layout.

Questions

Is it free?

For personal and other noncommercial use, yes; commercial use needs a license from the author. There is no paid tier and no account with us. You pay only for the hosted models you choose to use.

Which models can I use?

Local models through Ollama, llama.cpp or LM Studio, hosted ones through Anthropic or OpenAI keys, GitHub Copilot, OpenRouter, OpenCode Zen or any OpenAI-compatible endpoint, or a ChatGPT plan. ChatGPT Chat is an experimental extra: it drives a signed-in ChatGPT browser window, which OpenAI doesn’t officially support, so Atelier shows a warning first.

Does anything leave my machine?

Requests go to the model providers and connectors you set up, to the search engines and pages web search and fetch reach, and the desktop app checks for new versions every five minutes. There is no telemetry and no Atelier cloud.

Can I bring my existing skills, plugins and hooks?

Mostly. Atelier reads agent skills, commands, sub-agents and hooks where they already live, lists plugins you installed for other agents so you can switch them on or off, and can import MCP config. A few things differ, and the compatibility page lists them.

Can I see the prompts Atelier sends to the model?

Yes, all of them. Every system prompt, note and tool description is published verbatim in the documentation and lives in the repository, where you can also override them.

Which platforms are supported?

Desktop apps for macOS, Windows and Linux, and a web app you host with Docker. macOS is the most used. The Windows and Linux builds exist but have had less testing.

Why does my system warn about the installer?

macOS builds are signed with a Developer ID and notarized, so they open normally. Windows builds aren’t code-signed yet: choose More info, then Run anyway. Linux packages are unsigned.
